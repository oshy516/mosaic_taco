\section{Related Work}
\label{sec:related}

Existing approaches on optimizing loop nests and tensor programs can be broadly divided into \emph{schedule optimization} and \emph{execution space optimization}. While modern frameworks have extensively studied schedule optimization through polyhedral scheduling~\cite{ppcg,tc,polygeist,akg} and schedule-template search~\cite{halide,tvm}, execution space optimization remains dominated by heuristics and empirical tuning.

\paragraph{Analytical optimization.}
Analytical tile size selection has a long history on CPUs~\cite{mckinley-tss,lam-tss,pingali-tss,tss-revisited}. More recent approaches formulate tile size selection using polynomial~\cite{pluto-tss} or geometric programming~\cite{rajopadhye-gp,rajopadhye-igp}, often within compiler frameworks such as Pluto~\cite{pluto}, PPCG~\cite{ppcg}, and PolyMage~\cite{polymage}. TileMind~\cite{tilemind} further decouples tile size selection from compiler internals through an MILP formulation. These methods primarily target CPU cache residency and focus on tile size selection alone.

GPU execution space optimization is more challenging because tile sizes interact with thread block configurations, shared memory allocation, occupancy, and register pressure. A recent work~\cite{ppcg-tss} incorporates tile size selection in PPCG into its scheduling formulation, while EATSS~\cite{eatss} analytically models GPU tiling decisions. \name jointly optimizes tile sizes, block dimensions, shared memory placement, and register usage within a unified formulation, remaining independent of any particular compiler infrastructure.

\paragraph{Kernel-specific models.}
Several analytical models have been developed for specific GPU kernels such as GEMM and convolution~\cite{li-gemm,blis,saday-conv,conv-cache}. These approaches achieve high accuracy for their target kernels but are difficult to generalize. \name instead targets a broader class of affine kernels, including contractions, reductions, and stencil computations.

\paragraph{Search-based optimization.}
Modern systems increasingly rely on empirical search. Autotuners such as Ansor~\cite{ansor} and MetaSchedule~\cite{metaschedule}, and related systems for Halide~\cite{automatichalide} and Triton~\cite{triton} generate and evaluate many candidate configurations. Learning-based and dynamic-programming approaches further approximate this optimization space using predictive models or recursive search~\cite{hctuner,yuki-tss,Jangda2020dp,shirako-tss}. These techniques can be viewed as alternative ways of exploring the same execution space optimization problem.

Rather than searching over configurations, \name directly models GPU resource interactions and solves for execution parameters analytically. We therefore compare against both analytical methods (PPCG and EATSS) and the state-of-the-art search-based system MetaSchedule in \autoref{sec:eval}.
